# Commit Quality Protest

[![Artificial GitHub Activity](https://github.com/lologog/CommitQualityProtest/actions/workflows/activity.yml/badge.svg)](https://github.com/lologog/CommitQualityProtest/actions/workflows/activity.yml)

> Making the contribution graph greener without making the software better.

This repository is a small protest against evaluating software developers
based on the number of commits, GitHub activity streaks, or the color of
their contribution graph.

A GitHub Actions workflow updates `activity.log` once every hour and creates
a new commit.

The repository intentionally produces commits with almost no technical value.

---

## Why?

Because:

- one commit can represent several days of thoughtful engineering,
- fifty commits can represent automated noise,
- commit count does not measure code quality,
- activity graphs do not measure knowledge,
- green squares do not measure engineering impact.

---

## What This Repository Demonstrates

It is easy to automate visible GitHub activity.

It is much harder to:

- understand requirements,
- design reliable systems,
- review code properly,
- diagnose difficult failures,
- make good engineering decisions,
- maintain software over time.

---

## Conclusion

Commit quantity is easy to automate.

Software quality, engineering knowledge and meaningful project contributions are not.

**Measure engineering impact, not green squares.**
